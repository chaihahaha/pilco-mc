# 工程日志：MC-PILCO + 神经网络，为什么 cart-pole 甩杆还没学出来

这份文件记录实现过程中**测到的**每一个数字，以及每个数字排除掉了哪种解释。
结论在 README 的 "What happens on cart-pole"；这里是可以复现的过程。

## 1. 出发点

`pilco_pytorch` 的解析矩匹配之所以成立，是因为模型和控制器都被限制成"高斯可积"的
形状（ARD GP + 平方指数 RBF 网络）。把矩换成蒙特卡洛之后，这个约束消失了，模型可以
换成任意可微函数。

**但约束消失和问题变简单是两件不同的事。** 下面是测出来的差别。

## 2. 蒙特卡洛确实复现了解析矩

`tests/test_particles.py`，4σ 容差：

| 算子 | 对比对象 | 结果 |
| --- | --- | --- |
| 高斯采样 | `initial_particles` vs $(m,S)$ | 均值/协方差都在 MC 误差内 |
| 三角 | $\mathbb{E}[\sin],\mathbb{E}[\cos],\mathrm{Cov}[\sin,\cos]$ vs `TrigAugmentOp` | z ≤ 1.25 |
| 代价 | $\mathbb{E}[c],\mathrm{Var}[c]$ vs `SaturatingCostOp` | z ≤ 3.9 |
| GP | $\mathbb{E}[f_e],\mathrm{Cov}[f_e,f_f]$ vs `GpDynamicsOp.moments` | z ≤ 2.6 |

所以"把 `plan()` 换成 `rollout()`"是**估计量的改变**，不是模型的改变。这一条是
后面所有讨论的前提：出问题的地方不在估计量。

## 3. 逐步排除的解释

### 3.1 残差块初始化（已修）

第一版里残差块的第二层用正交初始化（gain $\sqrt2$），残差分支一上来就和主信号同量级，
两层之后激活发散。改成 **W2 零初始化**（块初始为恒等）后：

| | 一步 R²（1000 点，2000 epoch） |
| --- | --- |
| 非零 W2 | 0.41 |
| 零 W2 | 0.66 → 配合更多 epoch 达 0.94 |

修好了，但不是瓶颈（见 3.4）。

### 3.2 模型容量不是瓶颈

用 `pilco_pytorch` 训好的甩杆控制器（真实代价 12.8）采 400 步数据，拟合集成模型：

```
一步 R² = 0.977（400 条转移）
```

**模型对一步动力学的拟合非常好。** 所以"网络太弱/数据太少拟合不动"这个解释可以排除。

### 3.3 优化器会利用模型（已修，但带来新问题）

第一版（无不确定性惩罚）：

```
episode 1: predicted 33.76   realised 39.99
episode 2: predicted 33.50   realised 39.99
```

模型认为策略值 33.8，真实是天花板 40.0——典型的 model exploitation。加不确定性惩罚
$\lambda\,\mathbb{E}\|\mathrm{sd}\|$ 后：

| λ | predicted | realised |
| --- | --- | --- |
| 0.0 | 33.8 | 40.0（利用模型） |
| 0.2 | 35.4 | 39.5 |
| 2.0 | 39.9 | 39.95（冻结，安全但无用） |

惩罚只是在"利用"和"冻结"之间移动，没有产生学习。

### 3.4 真正的原因：想象轨迹在第 10 步之后就不真了

`scripts/diagnose_imagination.py`：用**好控制器**的数据拟合模型，然后比较
"模型想象的代价"与"真实代价"随规划时域的变化。

```
一步 R² = 0.977

  H   imagined     true   ratio
  5       4.95     4.99     1.0x
 10       9.84     9.98     1.0x
 15      14.71    12.79     1.2x
 20      19.37    12.79     1.5x
 30      28.91    12.80     2.3x
 40      38.72    12.80     3.0x
```

模型在 H≤10 与真实**完全一致**，之后彻底发散。发散后的轨迹就是"杆倒了"，代价恰好
每步 1.0，所以想象代价线性涨到 40。

**而甩杆需要大约 15 步的可信想象才会出现第一次收益**（先把能量泵上去，前 10 步代价
仍然是 1）。模型给不了 15 步。

这不是策略优化的问题：优化器在优化一条**错误的轨迹**。加大优化预算（200 → 800 步）
无变化，加数据（500 → 620 点）无变化，都是这个原因。

### 3.5 顺带测到的两个反例

- **balance 任务**（从竖直附近开始，H=30）也学不出来（24–27 / 30）。它只需要约
  10 步的可信想象，但数据覆盖的是"杆从竖直倒下去"的轨迹，最优策略要去的区域
  （把小车推到杆下面）没有数据。→ 覆盖问题。
- 集成 bootstrap 让成员在数据外分歧，但 400 点时分歧不足以表达"这里我不知道"。

## 4. 与解析版的对照

`pilco_pytorch` 在同一任务、同一数据预算下能学到 12.8。差别不在模型容量，在
**不确定性是否被传播**：

- 解析版把 GP 的**校准过的**预测不确定性逐步传下去。轨迹一旦离开数据，方差变大，
  期望代价在积分下被"惩罚"，规划器自然会避开。
- 蒙特卡洛版也有方差（粒子从模型分布里采样），但网络集成的方差没有校准，离开数据
  时几乎不涨，于是采样出的轨迹"自信地错"。

一句话：**PILCO 的 GP 先验在代替你做探索；换成网络之后，探索必须由数据覆盖或显式的
不确定性机制补上。**

## 5. 下一步（按预期收益排序）

1. **多步训练**：拟合时展开 k 步、惩罚 k 步误差，而不是只拟合一步转移。这是对 §3.4
   那张表的直接修复——让模型为漂移付出代价。
2. **校准的不确定性**：每个集成成员换成 GP，或用带温度/最后一层方差的 deep ensemble。
3. **把规划时域压到模型撑得住的长度**（≈10 步）并滚动重规划（MPC），代价是放弃
   "一次甩上去"的承诺。

## 6. 复现命令

```bash
python tests/test_particles.py            # 估计量验证
python scripts/diagnose_imagination.py    # §3.4 的表
python scripts/run_cartpole.py --episodes 4 --seed 0    # §3.3 的闭环数字
```

# 附：四个问题的实测回答（`scripts/answer_questions.py`）

## Q1 是 MC 让动力学模型不收敛吗？

**不是。** 模型一步拟合 R²=0.977（用已知好控制器的 400 条转移），MC 估计量也已验证
与解析矩一致（4σ）。想象轨迹不准有两个**互相独立**的原因：

**(a) 分布漂移 / 复合误差。** 模型在数据分布上训练，却被在自己的预测分布上查询。
`diagnose_imagination.py` 的表显示：H≤10 想象与真实完全一致，H=15 起发散到 3.0 倍。

更要命的是**想象的闭环本身是不稳定的**。同一个控制器，想象出来的粒子云散布（对状态
维取范数）：

| t | 模型散布 | 真实散布 | 比值 |
|---|---|---|---|
| 0 | 0.199 | 0.185 | 1.1 |
| 5 | 6.69 | 0.90 | 7.4 |
| 10 | 25.5 | 0.26 | 100 |
| 30 | 1665 | 0.88 | 1888 |
| 40 | 25471 | 0.57 | 44917 |

真实系统里控制器把偏差压住了；模型里同一套反馈把偏差放大——**模型误差破坏了反馈
回路**，粒子飞散，期望代价变成一堆无意义轨迹的平均。

**(b) 优化器也是独立缺口。** 把模型换成**真实动力学**（`OracleDynamics`，RK4 +
同样的过程噪声），250 步 Adam 只到 39.0（工作甩杆是 ~13，天花板 40）。加大预算：

| 步数 / 学习率 | 真实代价 |
|---|---|
| 250 / 3e-3 | 38.5 |
| 1000 / 1e-2 | 38.3 |
| 2000 / 3e-3 | **34.8** |

在缓慢改善，但离 13 很远。也就是说：**即使模型完美，一阶 Adam 在 MC 估计上也不足以
找到这个甩杆策略**；PILCO 的 BFGS + 线搜索 + 解析梯度做了大量工作。

顺带修掉一个真 bug：`optimise_policy` 原来在 `optimiser.step()` **之后**保存"最好策略"，
却把代价记在更新**之前**的参数上——记录 37.6、返回的策略实际值 39.99。改为更新前快照。

## Q2 加大粒子数能解决吗？

**不能。** 同一个模型，同一个好控制器，H=40 的想象代价：

| P | 16 | 64 | 256 | 1024 |
|---|---|---|---|---|
| H=40 | 38.57±0.46 | 38.76±0.17 | 38.51±0.13 | 38.56±0.03 |

16 个粒子就已经收敛，加粒子只是把误差棒缩在**错误的数**上。

但有一个重要细节：**值收敛得快，梯度不快**。与 8192 粒子参考梯度的余弦相似度：

| P | 16 | 64 | 128 | 512 |
|---|---|---|---|---|
| cos(g, g_ref) | 0.005 | 0.707 | **0.962** | 0.950 |

所以粒子数的瓶颈在梯度，不在值；默认 128 已经够。**粒子数不是本问题的瓶颈。**

## Q3 用 GMM / splatting 代替粒子行不行？

先纠正一个前提：**混合高斯本身的矩是闭式的**，

$$\mathbb{E}[x]=\sum_k w_k m_k,\qquad
\mathrm{Cov}[x]=\sum_k w_k(S_k+m_km_k^\top)-\mathbb{E}[x]\mathbb{E}[x]^\top .$$

"没有闭式矩匹配"指的从来不是混合的矩，而是**把一个高斯推过非线性之后、要求输出仍是
高斯**这一步。而这一步**可以绕开闭式积分**，有三条成熟路线：

1. **sigma points / 无迹变换（UT）**：用 $2D+1$ 个确定性点代替采样；
2. **cubature / Gauss–Hermite 求积**：更高阶；
3. **EKF 线性化**：最便宜，一阶。

实测（把一个高斯推过网络，与 20 万样本 MC 比）：

| 方法 | 均值误差 | 协方差相对误差 |
|---|---|---|
| UT，$2D{+}1=9$ 个点 | 0.17（尺度 2.12，约 8%） | 13% |

所以 **GMM-ADF 路线在数值上可行**：每个分量用 sigma points 传播，再重新拟合 K 个分量，
每步成本 $O(KD)$ 次模型调用而不是 P 个粒子。**但它治的是多模态**（"杆可能向左也可能
向右"），**不是数据外偏差**——所有分量的均值都在同一个错误的地方，混合再多也只是更
精细地描述那个错误。

## Q4 用分叉树（MCTS / 光线追踪 splitting）能解决吗？

树能买到的是**信任管理**，不是精度。

- 上面的表说明漂移是**偏差**（所有分支都收敛到"杆倒了"），不是方差。分支更多只是更
  精确地估计那个错误值。
- 树真正有用的两点：(i) **UCT 的探索奖励** $Q+c\sqrt{\ln N/n}$ ——给"没数过"的区域
  记账，这正是 PILCO 里 GP 方差扮演的角色；(ii) **滚动重规划（MPC）**——不必承诺
  40 步，每走几步就重新观测再规划，这直接绕开复合误差。
- 光线追踪里的对应物其实是：**splitting**（在关键事件处把一条路径分裂成多条带权副本）
  = 自适应粒子分配；**Russian roulette** = particle dropout（MC-PILCO 已在用）；
  **next event estimation** = 在节点上解析地算即时代价而不是采样。

## 结论：要修的是这三件事

1. **优化器**：一阶 Adam 在这个策略类上太弱（完美模型下 2000 步也只到 34.8）。用
   BFGS/线搜索、CEM/POPLIN，或保留 PILCO 那种低维参数化策略。
2. **多步训练**：让模型为漂移付出代价（§3.4 那张表的直接修复）。
3. **短时域滚动重规划 + 校准不确定性**：不承诺 40 步；让"我不知道"变成代价。
